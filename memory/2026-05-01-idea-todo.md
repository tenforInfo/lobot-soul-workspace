## 二、推荐的 `PLAN.md` 内容格式

你这个文档不要写成“设计说明书”，而是写成**持续追踪记录**。  
推荐固定成下面这个结构：

```md
# [项目名] Plan

> 状态：进行中 / 待确认 / 已完成 / 暂停

## 1. 目标
这个项目是干什么的，解决什么问题。

## 2. 当前重点
- 正在推进什么
- 最近最重要的 1-3 件事

## 3. 灵感与想法
- 临时想到的功能
- 聊天里提到但还没确认的点
- 可以以后再做的点

## 4. 待办
- [ ] 具体要做的事
- [ ] 需要确认的事

## 5. 已确认
- [x] 已经定下来的方向
- [x] 已经决定的实现方式

## 6. 备注
- 一些补充想法
- 临时状态
- 以后可能会变的东西
```

这个结构的好处是：

- 很适合“聊天完就记录”
- 不会太重
- 以后 AI 也容易自动分类
- 可以直接从聊天整理进来

## 三、你要的那个“另一个 agent”应该怎么工作

这个 agent 的职责，不是开发，而是**记录员 / 归档员**。

它的工作流程建议定义成：

### Agent 工作流
1. 聊天结束后，先判断内容属于哪个项目
2. 对比项目现有 `README.md`、`PLAN.md`、已有 todo
3. 判断：
   - 是新想法
   - 是已确认功能
   - 是待办
   - 还是临时灵感
4. 把内容整理成短条目
5. 写入对应项目的 `PLAN.md`
6. 如果内容还不确定，放到“灵感与想法”或“待确认”
7. 如果已经确认，就放到“当前重点”或“待办”

### 1. 放在一个地方还是分在各个项目里？

结论：分层存放，各有侧重。

* 集中存放（放在 `bunny_stack` / 集中工具中）
 * **适合放什么**：跨项目的高层优先级（这周重点推进哪 3 个项目）、全局性的突然灵感（不知放哪的先扔进 `global_scribbles`），以及**待分配**的想法。
 * **优势**：每天早上看一眼就知道全局情况。
* 分散存放（放在各项目的 `PLAN.md` 里）
 * **适合放什么**：跟这个代码库强相关的具体功能设计、API 规划、压测待办、踩坑记录。
 * **优势**：当你用 Cursor / Zed / 命令行在这个项目里写代码时，AI 能**直接**读到这个项目的 `PLAN.md`，它非常清楚当前的上下文和目标，不会被其他项目干扰。
